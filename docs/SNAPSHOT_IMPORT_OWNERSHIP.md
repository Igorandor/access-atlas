# Baseline file completion ownership

Verified September 27, 2026.

A controlled reproduction of the actual AccessReview callbacks found that an earlier file import could complete after a later successful import and replace its baseline. A pending import could also restore a baseline after Clear baseline. The file input and baseline actions remained enabled; these cases did not bypass a modal or disabled control. Original evidence is retained outside the submission in `research/atlas-snapshot-import-audit.mts` and `.json`.

Baseline imports now have a separate generation counter. Selecting another file invalidates the earlier completion, including its error. Clear baseline, Use current as baseline and unmount also invalidate pending file work. The native capture counter remains independent. File reads themselves are not cancelled; superseded completions cannot change baseline, view or error state.

Invalid files still preserve the last accepted baseline and show the existing error. The 2,000,000-byte file limit is checked before reading its text, then the strict snapshot schema and same-instance check apply. The audit's actual download Blob and import roundtrip preserved incomplete-capture warnings and unavailable metadata, and the resulting drift report remained partial. This is data validation, not proof of an imported file's provenance.

Four actual-component regression groups cover newer successful imports versus old success/error, explicit Clear/Use current replacement, newer invalid input retaining the previous baseline, and completion after unmount. The tests use the real schema with controlled file promises and no native transport. `npm run check` passes TypeScript, production builds and all **202 tests**.

Browser integration uses `research/atlas-snapshot-import-fixture.cjs` on port 3448 with the unchanged production bundle and layout. Its HTML loads a separate test-only File.text scheduling adapter: only `alpha-held.json` waits for a fixture response, while actual file contents remain in the browser. This boundary controls completion order without changing application callbacks. The local sample files are in `research/atlas-snapshot-import-files/`; Alpha is September 1, Beta September 15, and the current synthetic capture September 27. In Changes, choose Alpha, then Beta, and release Alpha with POST `{ "release": true }` to `/_test/control`. Repeat while using Clear baseline or Use current as baseline. GET `/_test/state` records the pending reads and releases, with zero native connections and writes. Partial.json exercises the ordinary unscheduled import. The fixture is bounded to four pending files and enumerated static assets. Browser observations are recorded separately by integration.

Browser verification passed against the production bundle: desktop imported Beta before releasing older Alpha, cleared a pending import, and selected the current capture during a pending import. None was overwritten. At a measured 375-pixel phone width, Clear remained effective after release; ordinary partial-file import retained both warnings and the partial-comparison label.
