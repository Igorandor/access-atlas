# Certification scope in standalone reports

The campaign report model and JSON export contained the certification scope, but the HTML and Markdown serializers omitted it. Two reports with different name prefixes and different treatment of disabled objects could therefore produce identical standalone documents when their captured objects happened to match. A reader could see a satisfied certification check without the boundaries that made it applicable.

Both formats now always include a compact Certification scope section: whether certification is required for closure, selected object kinds, the name prefix or All names, treatment of disabled accounts and applications, and the review due date. It remains present when optional finding, certification, receipt, timeline or activity sections are excluded. Text values use the existing HTML and Markdown escaping.

Certification calculations, closure rules, JSON shape, source timestamps and deadline semantics are unchanged. Disabled-object filtering applies to accounts and applications, as in the existing certification model. The generated date still describes report creation; Latest capture remains the time of the saved observation. Capture warnings still prevent a complete review and appear among the report limitations.

On 27 September 2026, `npm run check` passed the production frontend/server build and **159 tests**. Three added regressions cover distinct scopes over the same captured objects, all scope fields when optional sections are omitted, and hostile prefix escaping. The build retains the existing non-failing bundle-size and snapshot-schema import warnings.

The synthetic `research/atlas-report-scope.html` artifact outside this repository was generated by the current serializer for desktop/mobile visual review. It contains only fixture data, deliberately different report/capture dates, and a partial-capture warning. No native IRIS data was read or modified. Browser evidence is recorded by the integration reviewer.
